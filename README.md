# constellation-site

Static site for [constellation-works.com](https://constellation-works.com) — the front door over
the `constellation-works` projects.

`public/` is the deployed output; Cloudflare Pages serves it verbatim. The one build step
generates the Notes section into `public/notes/` and the analytics pages into
`public/analytics/` (both ignored by git) before each deploy.

- `public/index.html` — the home page, one file, styles inline.
- `notes/<slug>/index.md` — one note: front matter, Markdown, and the files it links to
  (data, `card.png` for the link preview). `build.py` documents the front matter.
- `build.py` — builds each note page, the `/notes/` index, the Atom feed,
  `/analytics/agents/` from the newest `data/analytics/<YYYY-MM-DD>/scorecards.json`,
  `/analytics/metrics/` from the newest `data/analytics/<YYYY-MM-DD>/metrics.json`,
  `/analytics/reliability/` from the newest snapshot's `reliability.json`,
  and `/analytics/experiments/` from its `experiments.json`.
  All analytics pages are static and make no Orbit calls.
- `public/assets/` — Notes stylesheet and theme scripts. Tokens mirror `index.html`.
- `public/brand/` — logo assets generated by the brand kit's `build.py`. Do not hand-edit an
  SVG here; regenerate it at the source and re-copy.

## Deploy

Pushes to `main` deploy via [.github/workflows/website.yml](.github/workflows/website.yml).
Requires repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`, and a
production environment variable `CLOUDFLARE_PAGES_PROJECT` naming the existing Pages project
bound to `constellation-works.com`.

## Notes

A note ships only when its front matter says `status: published` and has a `date`.
Drafts are skipped by the deploy build, so merging a draft does not publish it. Every
note goes through the marketing repo's approval workflow first; flipping a note to
`published` and pushing to `main` is the act of publishing.

Link cards are 1200x630 and generated by the brand kit (`marketing/brand/card.py`).

## Analytics

`/analytics/agents/` is generated by `build.py` from the newest
`data/analytics/<YYYY-MM-DD>/scorecards.json`. It lists implementers (all tiers,
and each complexity tier), reviewers (labelled provisional, plus a settled board
when the snapshot has one) and pilots. Each board prints its UTC window, a
one-line score key, and the unit beside every score. Rows under that board's
minimum support stay unranked. The page is rebuilt on each deploy and is not
committed; `public/analytics/` is gitignored, the same way `public/notes/` is.
The method is the [crew-rankings note](notes/crew-rankings-method/index.md).

`/analytics/metrics/` is generated by `analytics_page.py` (called from `build.py`) from the
newest `data/analytics/<YYYY-MM-DD>/metrics.json`. It shows the succeeded-run 30-day duration
board alongside 30-day boards for task completions, defects, tokens, cost, diff size, friction
and turns. The page states its UTC window once at the top; a board prints its own window only
when it differs. An at-a-glance tile row (blue improved, orange got worse, per each metric's
direction; `*` marks a rate derived on the page) links into four groups: Speed, Throughput,
Quality and Spend. Coverage and thin-sample warnings are computed from the snapshot. Daily
tables and per-model rows sit in `<details>`. The outcome-by-complexity board is an all-time
mix with no 30-day window. Charts are inline SVG generated at build time; the page makes no
Orbit calls. `public/assets/analytics.js` turns the groups into tabs; without JavaScript every
group renders stacked.

`/analytics/reliability/` uses the newest snapshot's `reliability.json`. Success and
failure rates use successes plus direct failures; cascaded failures (wrapper echoes)
are excluded from that denominator. Failure categories and other outcomes show counts
and shares of all recorded runs. Each board prints its exact 30-day UTC window and
denominator. The renderer reads only known aggregate counts and validated timestamps;
it does not publish job or activity identifiers, diagnostic labels or messages.

`/analytics/experiments/` includes only concluded experiments from the newest snapshot.
Picker cards (status, short question, arms, tasks, days, clear-better and clear-worse
counts) lead to one section per experiment: a readout strip (verdict, chosen arm, primary
metric, enrolled), the question (full text in `<details>`), why no decision was made, the
clear signals (cells whose interval excludes zero) and one metric × arm scorecard of
differences from control, primary row first. Each cell shows the value, a Better / Worse /
Leans / Same tag, an interval plot oriented worse-left/better-right by the metric's
direction, and the interval; only clear cells are shaded. Metrics unmeasured for every arm
fold into one line, exploratory metrics sit under `Other metrics (N)`, and an arms table
shows treatment delivery (tasks on the arm's own crew) and observed crews. The short
question is assembled from the readout's arms, primary metric, population and guardrails.
`analytics.js` shows one experiment at a time and adds a "Clear signals only" filter;
without JavaScript every experiment renders stacked. Per-arm means for every
outcome, medians for non-rate outcomes, supplied intervals and metric-specific
support appear only inside the collapsed `Raw per-arm outcomes` block. It prints the
cumulative UTC window from experiment start to readout. The statistical verdict
and recorded chosen arm are distinct: concluding an experiment does not imply a
winner, and unavailable measurements stay unavailable.
Names, hypotheses and verdict reasons use the snapshot's sanitized public text;
individual task/run records and diagnostic fields are not rendered.

Each analytics page also has a monthly archive: once a calendar month has
ended (a snapshot from a later month exists), that month's last snapshot is
rendered at `/analytics/<page>/<YYYY-MM>/` through the same renderer as the
live page, starting with 2026-11; nothing before the first routine snapshot
(2026-11-08) is backfilled. Every live and archived page carries a snapshot
picker (a plain link list, no JavaScript) listing Latest and each archived
month, and the `/analytics/` index lists the available months.

## Local preview

```sh
uv run --with markdown==3.8.2 python3 build.py --drafts   # drafts included, marked, noindex
python3 -m http.server -d public 8000
```
